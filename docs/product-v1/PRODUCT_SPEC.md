> 状态：M1 已完成并验收；M2-A（设计）已定稿，作为 M2-B 的实施依据；**M2-B 进行中**：M2-B1（数据基础，迁移 `0001`）、M2-B2.1（金融机构）、M2-B2.2（账户与多币种）已完成并提交；M2-B2.3（个人地区设置 `home_region`）已完成并提交；M2-B3（借记卡与预付卡图鉴、到期管理）已实现，待复审；银行卡-账户关联、支付渠道未开始。业务规则以本文档冻结版本为准。

## 1. 产品定位

X-UI 是 **Personal Global Finance Ledger（私人境外金融活动账本）**：记录个人在境外金融机构的账户、支付工具，以及（自 M3 起）通过它们发生的金融活动，用于判断和留存"需要记录的境外金融活动"。

## 2. 已冻结的产品决策

| # | 决策 |
|---|---|
| D1 | 第一阶段只有五个一级页面：总览、流水、账户、银行卡、设置。 |
| D2 | 不做：投资（账户与持仓）、实时汇率、手工换汇、信用卡及其账单与还款。 |
| D3 | 历史汇率未就绪前，金额按原始币种分别展示，**不生成 USD 或任何换算合计**。 |
| D4 | 不要求、不保存、不展示账户余额（无初始余额、无当前余额、无交易后余额更新）。 |
| D5 | **资金只存在于账户中。** 银行卡、支付渠道不持有资金；流水金额只记入一个真实资金来源账户。 |
| D6 | 四种地区相互独立、不可互相替代：机构所在地、账户所属法域（`account_country`）、发卡国家、商户国家（M3）。 |
| D7 | `account_country` = **账户开户合同所属金融机构法律实体所在法域**（详见 §4.3）。 |
| D8 | 每个账户必须属于一个金融机构（`institution_id` 必填）。 |
| D9 | 不保存完整卡号（PAN）、BIN、CVV、PIN；不提供"查看卡号"功能。 |
| D10 | 敏感卡号扫描不可绕过：自由文本中出现疑似卡号即拒绝保存。 |
| D11 | Wise 等多币种服务默认建模为**一个多币种账户**。 |
| D12 | 解除银行卡关联默认"结束"并保留历史；"删除"仅用于纠正误录。 |
| D13 | 预付卡可在创建时自动创建对应的储值账户，并作为其消费资金来源。 |
| D14 | 用户本国地区 `home_region` 默认 `CN`，可在设置中修改；每个用户独立保存（`user_preferences`），不是全局设置。 |
| D15 | 不开发成员角色；所有数据仍按 `user_id` 隔离。 |
| D16 | v1 共享代码放在新包 `@xui/ledger-shared`，不修改旧版 `@z-ui/shared`。 |
| D17 | M3 历史流水以交易发生时的快照为准，不依据当前关联关系重算（详见 §6）。 |
| D18 | 区分 **Event**（原始消费币种与金额）与 **Entry**（实际资金来源账户、实际扣款币种、实际扣款金额）。第一阶段不自动计算汇率和手续费，但允许记录用户从真实交易记录获得的实际扣款金额（详见 §6.1）。 |
| D19 | 默认来源推荐只返回三种结果：`exact_currency`、`conversion_required`、`no_match`；**不把账户默认币种当作消费币种**；推荐必须检查银行卡、账户、关联、币种的状态。 |

## 4. M2 规格：机构、账户、银行卡、支付渠道

### 4.1 目标

建立"资金在哪里、用什么工具支付"的基础资料，为 M3 判断境外金融活动提供：真实资金来源账户、其所属法域、实际使用的银行卡与支付渠道。

### 4.2 范围

| 对象 | 包含 | 排除 |
|---|---|---|
| 金融机构 | 银行、电子货币/支付机构（如 Wise、Revolut、PayPal、AlipayHK）、其他 | 券商、加密资产平台 |
| 账户 | 银行存款账户、电子货币账户、储值账户、其他持有资金的账户 | 信用账户、投资账户、现金 |
| 银行卡 | 借记卡（Debit）、预付卡（Prepaid）；实体或虚拟 | 信用卡及账单、还款 |
| 卡-账户关联 | 多对多；可限定币种；用途；默认消费来源；历史 | — |
| 支付渠道 | 设备钱包（Apple Pay、Google Pay 等）、支付服务（PayPal 等）、其他 | 转账方式（SWIFT/FPS/SEPA 等，归 M3 交易模型） |
| 设置 | `home_region`（默认 CN） | — |

### 4.3 地区字段定义

| 字段 | 含义 | 用途 |
|---|---|---|
| `institutions.country` | 机构注册地/总部（可空） | 仅展示、分组 |
| `accounts.account_country` | **账户开户合同所属金融机构法律实体所在法域** | M3 判断境外活动的依据 |
| `cards.issuing_country` | 发卡国家 | 仅展示 |
| `payment_channels.region` | 支付服务账户的注册地区（可空） | 仅展示 |
| merchant country | 商户所在地（M3，属于流水） | M3 判断 |
| `home_region` | 用户本国地区（每个用户的个人设置，默认 CN） | M3 判断"境外" |

`account_country` 的判定规则：

1. 以**账户协议与实际开户实体**为依据：与用户签订账户合同的那个法律实体在哪个法域注册/持牌，就填哪个法域。
2. 不是合作银行实际存放资金的地点（例如电子货币机构把客户资金存放在合作银行，不改变 `account_country`）。
3. 不从机构总部推断，不从银行卡发行国家推断，不从币种收款账户信息（如 Wise 的 USD 账户信息在美国）推断。
4. 一个账户只有一个 `account_country`。若开户实体变更（例如服务迁移到另一法律实体），应新建账户并关闭旧账户，而不是修改旧账户的地区（见 §6 历史完整性）。
5. 表单中该字段**必填且不预填**，旁附上述说明。

示例：Wise 账户若开户合同主体为 Wise Europe SA，则 `account_country = BE`；即使其 USD 收款信息位于美国、发卡国家为其他国家，亦不改变。

### 4.4 功能需求

**金融机构**
- 用户自建机构（无全局机构库）；前端可提供少量预设仅用于预填表单。
- 同名检测：规范化名称 + 国家相同即视为重复，提示"使用已有机构"；同名不同国家允许（视为不同法律实体）。
- 不上传 logo，以颜色 + 首字母头像展示。
- 有账户、银行卡或支付渠道引用时不可删除，只能归档。

**账户**
- 必须选择机构（表单内可直接新建机构）。
- 类型：银行账户（可选存款类型：活期/储蓄/定期/其他）、电子货币账户、储值账户、其他。
- 支持多个币种，恰好一个默认币种；币种可单独关闭。
- 可选账号尾号（最多 4 位），绝不保存完整账号。
- 状态：正常、冻结、关闭；可选开户/销户日期。
- 无任何余额字段或展示。

**银行卡**
- 独立存在，不直接属于某个账户；通过关联表与账户多对多。
- 字段：发卡机构、名称、卡组织、类型（仅借记/预付）、实体/虚拟、后四位、发卡国家、有效期（可选，年-月）、状态、备注。
- 表单中**没有卡号输入框**，只有 4 位后四位输入。
- 预付卡可勾选"同时创建储值账户"：自动创建储值账户（币种、`account_country` 由用户填写），并建立默认 `spending_source` 关联。
- 到期（M2-B3 实现说明）：有效期 `YYYY-MM` 表示有效至该月最后一天；页面区分"未到期 / 即将到期（默认 60 天内）/ 已过期 / 无到期日期"，按用户本地日期计算，可按到期状态筛选；到期不改变卡片状态（已过期 ≠ 停用），不发送通知。卡面为纯 CSS，只使用名称、发卡机构及其颜色、卡组织名称、形态、后四位与有效期月份。

**银行卡-账户关联**
- 用途（role）：
  - `spending_source` 消费资金来源：刷卡消费时扣款的账户。**预付卡的储值账户属于 `spending_source`。**
  - `top_up_source` 充值来源：为卡（或其储值账户）充值的账户。
  - `other` 其他。
- 币种范围：空 = 适用于该账户所有币种；或指定该账户的某一币种。
- 默认消费来源：每张卡在每个币种范围内至多一个默认 `spending_source`。
- 状态：有效、暂停、已结束。"解除关联" = 结束（记录结束日期，保留历史）；"删除" = 仅纠正误录。
- 默认来源推荐（`GET /cards/:id/spending-source?currency=`，算法见 DATA_MODEL §5）：
  - 输入的币种是 **Event 消费币种**；推荐的是资金来源账户，只有币种完全一致时才同时给出扣款币种。
  - 结果分三种：
    - `exact_currency`：存在合格的消费来源账户持有该币种的有效余额币种 → 推荐该账户，扣款币种 = 消费币种；
    - `conversion_required`：存在合格的消费来源账户，但都不持有该币种 → 推荐账户，**扣款币种留空**，列出该账户可用币种供用户选择（不把账户默认币种当作消费币种或扣款币种）；
    - `no_match`：没有合格来源（或银行卡不可用）。
  - 合格必须同时满足：银行卡有效、关联有效且用途为 `spending_source`、账户有效、相关币种有效。
  - 推荐只用于 M3 新建流水时预填，不改变任何数据。
- 关闭或冻结账户、关闭某个币种、冻结或关闭银行卡**不修改关联**（关联与默认标记保留，可在历史中查看），但这些来源不再被推荐给新交易；恢复有效后重新可被推荐。
- Wise 示例：一个 Wise 多币种账户 + Wise 借记卡，一条"所有币种"的默认 `spending_source` 关联。账户持有 USD 时，USD 消费 → `exact_currency`（Wise · USD）；账户只持有 HKD、EUR 时，USD 消费 → `conversion_required`（Wise，候选扣款币种 HKD、EUR，由用户依据真实记录选择并填写扣款金额）。

**支付渠道**
- 类型：设备钱包（`device_wallet`，如 Apple Pay、Google Pay）、支付服务（`payment_service`，如 PayPal）、其他（`other`）。
- 支付服务可指定一个"余额账户"（电子货币账户），表示该服务自身持有的资金；一个账户至多是一个渠道的余额账户。
- 资金来源：渠道可挂多张银行卡或多个账户（设备钱包只能挂银行卡），可设默认来源，可结束。
- 转账方式（SWIFT、FPS、SEPA 等）不是支付渠道，留给 M3 交易模型。
- 不重复统计：PayPal 余额付款 → 资金账户 = PayPal 余额账户；PayPal 绑定 HSBC 借记卡付款 → 资金账户 = HSBC 账户，银行卡、渠道仅为描述。

**设置**
- 设置 → 通用：`home_region`（默认 CN，ISO 3166-1 alpha-2；HK、MO、TW 为独立代码）。界面说明：本设置用于将来判断交易是否涉及境外金融活动；修改设置不会自动重分类已经保存的历史交易。界面仅在用户尚未保存过设置时显示"默认"标签（API `isDefault`）。（M2-B2.3 已实现）

### 4.5 前端页面

一级导航保持 D1 的五项。机构与支付渠道作为"账户"页的标签页。

| 路由 | 内容 |
|---|---|
| `/accounts` | 标签页：账户 · 机构 · 支付渠道 |
| `/accounts/:id` | 账户详情：基本信息、币种、关联银行卡（按币种范围分组，含历史）、相关支付渠道、备注 |
| `/accounts/channels/:id` | 支付渠道详情：余额账户、资金来源 |
| `/cards` | 银行卡列表（卡面网格 / 表格） |
| `/cards/:id` | 银行卡详情：卡面（仅 `•••• 1234`）、关联账户（含历史）、所属支付渠道 |
| `/settings` | 新增"通用 → 本国地区" |

交互要求：
- 列表：搜索、筛选（类型、国家、币种、状态、机构、卡组织、关联对象、即将过期）；已关闭/归档默认隐藏，可切换显示。
- 账户详情显示关联银行卡；银行卡详情显示关联账户；两侧使用同一关联组件，操作后两侧同步刷新。
- "解除关联"与"删除记录"文案区分清楚：前者提示"保留历史"，后者提示"仅用于纠正误录"。
- 任何页面不显示余额、金额合计或换算金额；总览页在 M2 保持占位。
- 视觉沿用 M1（深色主题、蓝色强调、卡片、表格、统一弹窗与表单）。

### 4.6 安全与隐私
- 请求体严格校验，出现 `pan`、`cardNumber`、`cvv`、`cvc`、`pin`、`bin` 等未知字段直接拒绝。
- 所有自由文本（名称、备注、账号尾号）做敏感信息扫描；命中即拒绝，**无绕过选项**。
- 审计日志只记录 id 与后四位，不记录请求体。

## 5. 不在 M2 范围
流水与统计（M3）、商户国家、余额、换算、信用卡、投资、PAN 存储与查看、BIN 查询与存储、虚拟卡挂靠实体卡、换卡关系、联名账户与持有人信息、成员角色、总览页数据。

## 6. 对 M3 的约束（多币种扣款与历史数据完整性）

### 6.1 Event 与 Entry

一笔金融活动分为两层：

| 层 | 含义 | 内容 |
|---|---|---|
| **Event** | 原始交易本身 | 原始消费币种、原始金额、商户国家、实际使用的银行卡与支付渠道、转账方式、发生日期 |
| **Entry** | 资金实际怎么动 | 真实资金来源账户、实际扣款币种、实际扣款金额、账户地区快照 |

示例：Wise 卡支付 10 USD，实际从 HKD 余额扣款。

| | 值 |
|---|---|
| Event | 10.00 USD，银行卡 Wise Debit，商户国家 US |
| Funding account | Wise 多币种账户 · HKD |
| Entry | 实际扣款 HKD 金额（用户依据 Wise 交易记录填写，例如 78.30 HKD） |

规则：
1. 统计与境外活动判断按 Entry 的资金账户与币种进行；Event 金额只描述原始交易，不另行计入金额统计，不会重复计算。
2. 第一阶段**不自动计算汇率与手续费**，不保存推算出的汇率，不生成换算合计。
3. Entry 币种与 Event 币种相同时，前端可把 Event 金额预填为扣款金额，但两者分别保存。
4. 币种不同时，扣款金额由用户依据真实交易记录填写；暂时未知可留空并标记"待补录"，系统不估算。待补录的 Entry 不计入金额统计，单独列出。
5. Entry 币种必须是资金来源账户的有效币种。
6. `conversion_required` 推荐结果只提供候选扣款币种，用户必须明确选择。

### 6.2 历史数据完整性

M3 交易模型必须满足：

1. 每笔流水保存交易发生时的**真实资金来源账户**与**资金币种**（Entry），以及原始消费币种与金额（Event）。
2. 每笔流水保存交易发生时的**来源账户地区快照**（`account_country` 当时的值），以及当时的 `home_region` 快照。
3. 每笔流水保存**实际使用的银行卡**与**支付渠道**（可空）。
4. 历史流水**不依据当前关联关系重新推算**；默认来源查找只用于新建流水时的预填。
5. 修改账户的 `account_country`、修改 `home_region`、结束或删除关联，**都不改变历史流水与历史统计**。历史流水的境外判断只使用其自身保存的 `home_region` 快照，不得使用当前的 `home_region` 重新解释或自动重分类。
6. 被流水引用的账户、银行卡、支付渠道不可删除（只能关闭/归档）。

字段级要求见 [DATA_MODEL.md](DATA_MODEL.md) §8。
