## 1. 产品定位

X-UI 是 **Personal Global Finance Ledger（私人境外金融活动账本）**：记录个人在境外金融机构的账户、支付工具，以及（自 M3 起）通过它们发生的金融活动，用于判断和留存"需要记录的境外金融活动"。

## 2. 已冻结的产品决策

## 4. M2 规格：机构、账户、银行卡、支付渠道

### 4.1 目标

建立"资金在哪里、用什么工具支付"的基础资料，为 M3 判断境外金融活动提供：真实资金来源账户、其所属法域、实际使用的银行卡与支付渠道。

### 4.2 范围

| 对象 | 包含 | 排除 |
|---|---|---|
| 金融机构 | 银行、电子货币/支付机构（如 Wise、Revolut、PayPal、AlipayHK）、其他 | 券商、加密资产平台 |
| 账户 | 银行存款账户、电子货币账户、储值账户、其他持有资金的账户 | 信用账户、投资账户、现金 |
| 银行卡 | 借记卡（Debit）、预付卡（Prepaid）；实体或虚拟 | 信用卡及账单、还款 |
| 卡-账户关联 | 多对多；可限定币种；用途；默认消费来源；历史 | — |
| 支付渠道 | 设备钱包（Apple Pay、Google Pay 等）、支付服务（PayPal 等）、其他 | 转账方式（SWIFT/FPS/SEPA 等，归 M3 交易模型） |
| 设置 | `home_region`（默认 CN） | — |

### 4.3 地区字段定义

| 字段 | 含义 | 用途 |
|---|---|---|
| `institutions.country` | 机构注册地/总部（可空） | 仅展示、分组 |
| `accounts.account_country` | **账户开户合同所属金融机构法律实体所在法域** | M3 判断境外活动的依据 |
| `cards.issuing_country` | 发卡国家 | 仅展示 |
| `payment_channels.region` | 支付服务账户的注册地区（可空） | 仅展示 |
| merchant country | 商户所在地（M3，属于流水） | M3 判断 |
| `home_region` | 用户本国地区（每个用户的个人设置，默认 CN） | M3 判断"境外" |

`account_country` 的判定规则：

1. 以**账户协议与实际开户实体**为依据：与用户签订账户合同的那个法律实体在哪个法域注册/持牌，就填哪个法域。
2. 不是合作银行实际存放资金的地点（例如电子货币机构把客户资金存放在合作银行，不改变 `account_country`）。
3. 不从机构总部推断，不从银行卡发行国家推断，不从币种收款账户信息（如 Wise 的 USD 账户信息在美国）推断。
4. 一个账户只有一个 `account_country`。若开户实体变更（例如服务迁移到另一法律实体），应新建账户并关闭旧账户，而不是修改旧账户的地区（见 §6 历史完整性）。
5. 表单中该字段**必填且不预填**，旁附上述说明。

示例：Wise 账户若开户合同主体为 Wise Europe SA，则 `account_country = BE`；即使其 USD 收款信息位于美国、发卡国家为其他国家，亦不改变。

### 4.4 功能需求

**金融机构**
- 用户自建机构（无全局机构库）；前端可提供少量预设仅用于预填表单。
- 同名检测：规范化名称 + 国家相同即视为重复，提示"使用已有机构"；同名不同国家允许（视为不同法律实体）。
- 不上传 logo，以颜色 + 首字母头像展示。
- 有账户、银行卡或支付渠道引用时不可删除，只能归档。

**账户**
- 必须选择机构（表单内可直接新建机构）。
- 类型：银行账户（可选存款类型：活期/储蓄/定期/其他）、电子货币账户、储值账户、其他。
- 支持多个币种，恰好一个默认币种；币种可单独关闭。
- 可选账号尾号（最多 4 位），绝不保存完整账号。
- 状态：正常、冻结、关闭；可选开户/销户日期。
- 无任何余额字段或展示。

**银行卡**
- 独立存在，不直接属于某个账户；通过关联表与账户多对多。
- 字段：发卡机构、名称、卡组织、类型（仅借记/预付）、实体/虚拟、后四位、发卡国家、有效期（可选，年-月）、状态、备注。
- 表单中**没有卡号输入框**，只有 4 位后四位输入。
- 预付卡可勾选"同时创建储值账户"：自动创建储值账户（币种、`account_country` 由用户填写），并建立默认 `spending_source` 关联。
- 到期（M2-B3 实现说明）：有效期 `YYYY-MM` 表示有效至该月最后一天；页面区分"未到期 / 即将到期（默认 60 天内）/ 已过期 / 无到期日期"，按用户本地日期计算，可按到期状态筛选；到期不改变卡片状态（已过期 ≠ 停用），不发送通知。卡面为纯 CSS，只使用名称、发卡机构及其颜色、卡组织名称、形态、后四位与有效期月份。

**银行卡-账户关联**
- 用途（role）：
  - `spending_source` 消费资金来源：刷卡消费时扣款的账户。**预付卡的储值账户属于 `spending_source`。**
  - `top_up_source` 充值来源：为卡（或其储值账户）充值的账户。
  - `other` 其他。
- 币种范围：空 = 适用于该账户所有币种；或指定该账户的某一币种。
- 默认消费来源：每张卡在每个币种范围内至多一个默认 `spending_source`。
- 状态：有效、暂停、已结束。"解除关联" = 结束（记录结束日期，保留历史）；"删除" = 仅纠正误录。
- 默认来源推荐（`GET /cards/:id/spending-source?currency=`，算法见 DATA_MODEL §5）：
  - 输入的币种是 **Event 消费币种**；推荐的是资金来源账户，只有币种完全一致时才同时给出扣款币种。
  - 结果分三种：
    - `exact_currency`：存在合格的消费来源账户持有该币种的有效余额币种 → 推荐该账户，扣款币种 = 消费币种；
    - `conversion_required`：存在合格的消费来源账户，但都不持有该币种 → 推荐账户，**扣款币种留空**，列出该账户可用币种供用户选择（不把账户默认币种当作消费币种或扣款币种）；
    - `no_match`：没有合格来源（或银行卡不可用）。
  - 合格必须同时满足：银行卡有效、关联有效且用途为 `spending_source`、账户有效、相关币种有效。
  - 推荐只用于 M3 新建流水时预填，不改变任何数据。
- 关闭或冻结账户、关闭某个币种、冻结或关闭银行卡**不修改关联**（关联与默认标记保留，可在历史中查看），但这些来源不再被推荐给新交易；恢复有效后重新可被推荐。
- Wise 示例：一个 Wise 多币种账户 + Wise 借记卡，一条"所有币种"的默认 `spending_source` 关联。账户持有 USD 时，USD 消费 → `exact_currency`（Wise · USD）；账户只持有 HKD、EUR 时，USD 消费 → `conversion_required`（Wise，候选扣款币种 HKD、EUR，由用户依据真实记录选择并填写扣款金额）。

**支付渠道**
- 类型：设备钱包（`device_wallet`，如 Apple Pay、Google Pay）、支付服务（`payment_service`，如 PayPal）、其他（`other`）。
- 支付服务可指定一个"余额账户"（电子货币账户），表示该服务自身持有的资金；一个账户至多是一个渠道的余额账户。
- 资金来源：渠道可挂多张银行卡或多个账户（设备钱包只能挂银行卡），可设默认来源，可结束。
- 转账方式（SWIFT、FPS、SEPA 等）不是支付渠道，留给 M3 交易模型。
- M2-B5 实现说明：渠道在「账户 → 支付渠道」标签页中管理（不新增一级页面），详情页 `/accounts/channels/:id` 分「当前来源」「历史来源（已结束）」显示；界面中余额账户称为"资金账户"，不显示任何余额、金额或汇率。来源可"结束"（保留历史、清除默认、不可恢复，可重新添加为新记录）或"删除记录"（仅纠正误录）；渠道可归档（来源不变）或删除（一并删除其来源记录，银行卡与账户不受影响）。账户详情与银行卡详情列出相关渠道并可跳转。新指定的服务机构须为有效机构；已归档的渠道照常可管理。
- 不重复统计：PayPal 余额付款 → 资金账户 = PayPal 余额账户；PayPal 绑定 HSBC 借记卡付款 → 资金账户 = HSBC 账户，银行卡、渠道仅为描述。

**设置**
- 设置 → 通用：`home_region`（默认 CN，ISO 3166-1 alpha-2；HK、MO、TW 为独立代码）。界面说明：本设置用于将来判断交易是否涉及境外金融活动；修改设置不会自动重分类已经保存的历史交易。界面仅在用户尚未保存过设置时显示"默认"标签（API `isDefault`）。（M2-B2.3 已实现）

### 4.5 前端页面

一级导航保持 D1 的五项。机构与支付渠道作为"账户"页的标签页。

| 路由 | 内容 |
|---|---|
| `/accounts` | 标签页：账户 · 机构 · 支付渠道 |
| `/accounts/:id` | 账户详情：基本信息、币种、关联银行卡（按币种范围分组，含历史）、相关支付渠道、备注 |
| `/accounts/channels/:id` | 支付渠道详情：余额账户、资金来源 |
| `/cards` | 银行卡列表（卡面网格 / 表格） |
| `/cards/:id` | 银行卡详情：卡面（仅 `•••• 1234`）、关联账户（含历史）、所属支付渠道 |
| `/settings` | 新增"通用 → 本国地区" |

交互要求：
- 列表：搜索、筛选（类型、国家、币种、状态、机构、卡组织、关联对象、即将过期）；已关闭/归档默认隐藏，可切换显示。
- 账户详情显示关联银行卡；银行卡详情显示关联账户；两侧使用同一关联组件，操作后两侧同步刷新。
- "解除关联"与"删除记录"文案区分清楚：前者提示"保留历史"，后者提示"仅用于纠正误录"。
- 任何页面不显示余额、金额合计或换算金额；总览页在 M2 保持占位。
- 视觉沿用 M1（深色主题、蓝色强调、卡片、表格、统一弹窗与表单）。

### 4.6 安全与隐私
- 请求体严格校验，出现 `pan`、`cardNumber`、`cvv`、`cvc`、`pin`、`bin` 等未知字段直接拒绝。
- 所有自由文本（名称、备注、账号尾号）做敏感信息扫描；命中即拒绝，**无绕过选项**。
- 审计日志只记录 id 与后四位，不记录请求体。

## 5. 不在 M2 范围
流水与统计（M3）、商户国家、余额、换算、信用卡、投资、PAN 存储与查看、BIN 查询与存储、虚拟卡挂靠实体卡、换卡关系、联名账户与持有人信息、成员角色、总览页数据。

## 6. 对 M3 的约束（多币种扣款与历史数据完整性）

### 6.1 Event 与 Entry

一笔金融活动分为两层：

| 层 | 含义 | 内容 |
|---|---|---|
| **Event** | 原始交易本身 | 原始消费币种、原始金额、商户国家、实际使用的银行卡与支付渠道、转账方式、发生日期 |
| **Entry** | 资金实际怎么动 | 真实资金来源账户、实际扣款币种、实际扣款金额、账户地区快照 |

示例：Wise 卡支付 10 USD，实际从 HKD 余额扣款。

| | 值 |
|---|---|
| Event | 10.00 USD，银行卡 Wise Debit，商户国家 US |
| Funding account | Wise 多币种账户 · HKD |
| Entry | 实际扣款 HKD 金额（用户依据 Wise 交易记录填写，例如 78.30 HKD） |

规则：
1. 统计与境外活动判断按 Entry 的资金账户与币种进行；Event 金额只描述原始交易，不另行计入金额统计，不会重复计算。
2. 第一阶段**不自动计算汇率与手续费**，不保存推算出的汇率，不生成换算合计。
3. Entry 币种与 Event 币种相同时，前端可把 Event 金额预填为扣款金额，但两者分别保存。
4. 币种不同时，扣款金额由用户依据真实交易记录填写；暂时未知可留空并标记"待补录"，系统不估算。待补录的 Entry 不计入金额统计，单独列出。
5. Entry 币种必须是资金来源账户的有效币种。（M3 批准例外 P7：历史补录经逐条确认、或更正时沿用原有 Entry，可以使用已关闭币种，见 §7.6；当前交易仍须为有效币种。）
6. `conversion_required` 推荐结果只提供候选扣款币种，用户必须明确选择。

### 6.2 历史数据完整性

M3 交易模型必须满足：

1. 每笔流水保存交易发生时的**真实资金来源账户**与**资金币种**（Entry），以及原始消费币种与金额（Event）。
2. 每笔流水保存交易发生时的**来源账户地区快照**（`account_country` 当时的值），以及当时的 `home_region` 快照。（M3 定稿：快照取保存时的值并记录来源；经批准的例外为补录时用户声明的本国地区 P4 与逐笔快照更正 P5，见 §7.5、§7.6。）
3. 每笔流水保存**实际使用的银行卡**与**支付渠道**（可空）。
4. 历史流水**不依据当前关联关系重新推算**；默认来源查找只用于新建流水时的预填。
5. 修改账户的 `account_country`、修改 `home_region`、结束或删除关联，**都不改变历史流水与历史统计**。历史流水的境外判断只使用其自身保存的 `home_region` 快照，不得使用当前的 `home_region` 重新解释或自动重分类。
6. 被流水引用的账户、银行卡、支付渠道不可删除（只能关闭/归档）。

字段级要求见 [DATA_MODEL.md](DATA_MODEL.md) §8（M2 时期的要求）与 §10（M3 正式定义）。

## 7. M3 规格：境外金融活动账本

> 依据：M3-A.2 为准，未覆盖处继承 M3-A.1、M3-A；P1–P9 已获用户批准（[M3_DECISIONS.md](M3_DECISIONS.md)）。数据结构见 [DATA_MODEL.md](DATA_MODEL.md) §10，接口见 [API_SPEC.md](API_SPEC.md) §5，测试见 [TEST_PLAN.md](TEST_PLAN.md) §5。§6 的约束全部继续有效，经批准的例外已在该处标注。

### 7.1 定位与范围

X-UI 自 M3 起是能够准确记录**境外金融活动**的账本：记录通过真实账户（以及用于描述的银行卡、支付渠道）发生的消费、退款与汇款，按交易自身保存的快照判断是否属于境外活动，并按原币种统计。

不做：投资、信用卡、实时汇率、手工换汇（同一账户内换币）、余额（D4）、换算合计（D3）、自动推算汇率或手续费、永久删除交易。

### 7.2 交易类型与方向

| 类型 | 含义 | Entry |
|---|---|---|
| `merchant_spend` 商户消费 | 用银行卡、支付渠道或账户向商户付款；包括境外商户消费、境外账户境内消费、扣款币种与消费币种不同的消费 | 恰好 1 条 `out` |
| `merchant_refund` 商户退款 | 商户退回款项 | 恰好 1 条 `in` |
| `own_transfer` 本人调拨 | 本人账户之间的资金移动：本人跨境汇款、境外账户间调拨、境外本地调拨 | 两侧都已登记：一出一入两条；一侧是未登记的本人账户：1 条 |
| `third_party_transfer` 第三方汇款 | 与他人之间的汇款：汇给他人（`out`）或他人汇入（`in`） | 恰好 1 条 |

- 金额恒为正，方向由 `out`（资金离开该账户）/ `in`（资金进入该账户）表示。
- 交易类型建立后不可修改；录错类型时作废并新建。
- 本人调拨的两条 Entry 必须是两个不同账户；同一账户内换币不属于 M3（D2）。
- 本人调拨可以跨币种（例如 HKD 账户调往 USD 账户），两侧各记实际金额，不推算汇率。

### 7.3 Event 与 Entry

| 层 | 含义 |
|---|---|
| Event | 交易某一版本的原始事实：类型、发生日期、原始币种与金额、商户与商户国家、实际使用的银行卡与支付渠道、转账方式、对手方、`home_region` 快照、地域分类 |
| Entry | 该版本中**一个真实账户**的资金变动：方向、账户、币种、实际金额（可待补录）、账户法域快照 |

Event 金额的含义：

| 类型 | Event 金额 |
|---|---|
| 消费 / 退款 | 商户交易金额 / 退款金额（商户标价币种），必填 |
| 本人调拨、第三方汇出 | 汇款凭证上标明的**汇出本金**及其币种，必填（汇出币种可以不同于扣款币种） |
| 第三方汇入 | 对方凭证上的汇出本金；**对方金额未知时可以为空**（P8） |

- `out` Entry 记实际扣款总额（可能含费用），`in` Entry 记实际到账额；Event 金额从不表示到账额。
- Event 与 Entry 的币种、金额是相互独立的事实；系统**不**由差额推算汇率或手续费，也不保存差额。
- 跨币种扣款（例如 Wise 卡消费 10 USD、从 HKD 余额扣款）：扣款金额由用户依据真实记录填写，未知时为"待补录"（pending），不估算（§6.1）。
- 不重复统计：每条 Entry 只计入它自己的账户；Event 金额不参与统计；本人调拨的两侧单独列示，不计入消费或外部收支；PayPal 余额付款与 PayPal 绑卡付款各只计入一个资金账户（§4.4）。

### 7.4 地区与三态分类

**各侧的地区**

| 一侧 | 依据 |
|---|---|
| 已登记账户 | Entry 保存的账户法域快照（D7：开户合同主体所在法域） |
| 未登记的本人账户、第三方账户 | 转账对手方法域 `counterparty_country`，**定义与 D7 相同**：该账户开户合同主体所在法域；不是对方居住地，也不是收款路径；本人账户一侧必填，第三方可为未知（P3） |
| 商户 | 商户所在地，可为未知（Q4） |

**禁止推断**：任何一侧的地区都不得从收款账户信息（例如 Wise 的 USD 收款信息在美国、香港 FPS 收款信息）、IBAN 国家前缀、SWIFT / BIC 国家代码、转账方式、发卡国家、机构总部、币种、渠道地区推断。表单中对手方法域与账户法域一样附说明、不预填。

**三态**（以交易自身保存的 `home_region` 快照 H 判断）

| 状态 | 含义 | 判定 |
|---|---|---|
| `foreign` 已确认境外 | 至少一个已知的一侧不在 H | 任一已知侧 ≠ H |
| `domestic` 已确认纯境内 | 所有侧都已知，且都在 H | **不予保存**（P2） |
| `undetermined` 信息不足 | 没有已知的境外一侧，但有一侧未知 | 例如境内账户在国家未知的商户消费；本国账户汇给法域未知的第三方 |

- **未知不等于境内**：信息不足的交易可以保存，在统计中单独列出，既不并入境外也不并入境内；用户补充信息后经事实更正重新分类。
- 已确认纯境内的交易不属于境外金融活动，新建与更正（包括快照更正）后成为纯境内的版本都被拒绝，界面提示"不属于境外金融活动"，更正场景提示作废该交易。
- 转账另有细分：境内→境外（`outbound`）、境外→境内（`inbound`）、境外跨法域（`foreign_cross_border`）、境外本地调拨（`foreign_local`，例如香港账户之间），以及一侧未知的四种情形；消费另记商户一侧（境外 / 境内 / 未知）。
- 判断只使用交易自身保存的快照；修改设置、账户法域或分类规则代码都不会改变已保存的分类。

### 7.5 历史版本：备注、补录金额、事实更正、快照更正、作废

| 操作 | 内容 | 是否生成版本 |
|---|---|---|
| 备注修正 | 修改备注；备注是用户说明，**不属于交易事实**，作废后仍可修改，不保留修改历史（P9） | 否 |
| 补录金额 | 把待补录的扣款 / 到账金额填为确认金额，其余不变 | 是 |
| 事实更正 | 修正日期、金额、币种、账户、卡、渠道、商户、对手方、转账方式、补录声明等事实；必须填写原因 | 是 |
| 快照更正（P5） | 当初记录错的 `home_region` 快照或某账户法域快照；用户对**单笔**交易显式提交新值并填写原因，确认前展示旧值 → 新值及分类变化；不提供批量 | 是 |
| 作废 | 交易不再计入统计，全部版本保留；终态，不能恢复，不能永久删除（Q7） | 否（交易状态变化） |

- 每次修改必须基于当前版本（乐观并发）；旧版本与其 Entry 永久保留，可查看。
- 事实更正中账户不变的 Entry 沿用原快照；改用新账户时取该账户保存时的法域；`home_region` 沿用原值。
- 只有用户显式的快照更正才能改变新版本的快照事实；设置变化从不触发任何修改。

### 7.6 历史补录与已关闭币种

- 新建时用户声明"当前交易"或"历史补录"（`record_mode`）。补录是**用户的声明**：系统不证实交易确实发生，也不证实发生时账户、币种、银行卡的状态；不按日期强制判定，界面在发生日较早或所选账户 / 币种不是有效状态时提示（P6）。
- 已关闭的账户币种（P7）只能在两种情形使用：历史补录中由用户对该条 Entry 逐条确认；或更正时沿用原有 Entry（同一账户、同一币种）。当前交易仍须使用有效币种。账户上从未登记的币种不能使用，需先在账户中添加（可直接以"已关闭"状态添加）；系统不推断币种的开通或关闭日期。
- 系统只记录**保存时**币种的状态，界面标为"保存时状态"，从不表述为交易时状态。已关闭或冻结的账户、已过期或停用的银行卡、已归档的渠道都可用于补录（只提示）。
- 补录时可声明当时的本国地区（P4），与当前设置无关，不修改设置；不声明则取保存时的设置值。
- 补录模式下不自动套用默认来源推荐（当前关联不代表历史），只作参考。

### 7.7 统计口径

- 只统计**有效交易的当前版本**中**已确认**的 Entry；作废交易、被取代的版本、待补录金额都不计入金额（待补录只列笔数）。
- 一律按原币种分别统计，不跨币种合计（D3），Event 金额不参与统计。
- 结果分三块：已确认境外、信息不足、已确认境内（后者在 P2 下恒为空）；任何一块都不并入另一块。
- 分组：交易类型 × 方向 × 币种 × 细分（商户一侧 / 转账细分）× 账户一侧（境外 / 境内）。消费与退款分开列示，不自动抵扣；本人调拨的汇出额与到账额分开列示，从不相加；第三方汇出与汇入分开。
- 期间按发生日期；期间内交易保存时的 `home_region` 不同时，结果提示所涉及的本国地区，但每笔仍按自己的快照判断。

### 7.8 重复提交与幂等

- 新建、更正、作废必须携带客户端生成的幂等键；同一键的重复请求只重放**首次成功操作**的结果（不是交易的最新状态），内容不同则拒绝。响应丢失后安全重试，不会产生第二笔交易或第二次更正。前端禁用按钮只是辅助。
- 新建的幂等键永久保留；更正、作废的幂等键保留 30 天，过期后的重试因版本已变化或已作废而被拒绝，不会重复写入。
- 备注修改不使用幂等键（重复提交结果相同）。

### 7.9 历史完整性与删除保护

- 被任何版本（包括被取代的版本与已作废的交易）引用的账户、账户币种、银行卡、支付渠道不可删除，只能关闭或归档（§6.2）。
- 交易及其版本没有删除功能；数据库层拒绝删除，只有删除用户时随用户整体级联删除（v1 不提供删除用户的接口）。

### 7.10 页面

- **流水**：交易列表（筛选：期间、类型、账户、卡、渠道、币种、待补录、三态、补录声明、状态）；新建表单（选择卡时用默认来源推荐预填，补录模式只作参考；`conversion_required` 必须选择扣款币种）；待补录列表；交易详情（当前版本、版本历史与差异、补录金额、事实更正、快照更正、作废、备注）。
- **总览**：统计三块（§7.7）。
- 账户、银行卡、渠道的删除确认提示"被 N 笔流水引用，只能关闭 / 归档"。
- 任何页面不显示余额、换算金额、汇率或由差额推算的手续费。
